# RepoLens — UX Specification

_Phase 2 output (UX Researcher)._

## Principles

1. **Answer first, then evidence.** Every page opens with the number or list that answers the page's
   question; supporting detail is one click deeper, never above the fold.
2. **Dense, not busy.** Tables over cards where the data is tabular. One accent colour for actions,
   semantic colours only for severity and score.
3. **Predictable navigation.** The repository shell (header + tabs) is identical on every repository
   page; URL state is the source of truth for filters and the selected analysis.
4. **Keyboard first.** `⌘K` command palette, `/` focuses search, `j/k` moves through findings,
   `Enter` opens, `Esc` closes. Every interactive element is reachable by Tab with a visible focus ring.
5. **Never lie about state.** Loading, empty, error and stale states are distinct and explicit.

## Navigation

- **Global header** (all pages): logo → home, `Repositories` (authed), command palette trigger, theme
  toggle, user menu or "Sign in with GitHub". Demo pages show a `Demo data` pill next to the logo.
- **Repository shell** (all `/r/:owner/:name/*` pages): repository name with GitHub link, analysis
  selector (commit sha, date, "latest" indicator), `Re-analyze` button (owner only), and tabs
  `Overview · Findings · Architecture · History`.

## Page hierarchy and flows

### Landing `/`

Hero: one sentence, two actions (`Explore demo`, `Sign in with GitHub`). Below: a live miniature of the
demo dashboard's score ring and top findings (real data from the demo analysis), then three short
"how it works" steps (clone → analyze → act) and an honest "What it measures" list. No testimonials, no
fake logos.

### Repository picker `/repos`

Search input (auto-focused), list of GitHub repositories with language, visibility, last push,
and status (`Never analyzed`, `Analyzed 3d ago · 74`, `Analyzing…`). Row action: `Analyze` or `Open`.
Non-TS/JS repositories are listed but marked "Limited analysis (no AST)".
Empty: no repositories → explain GitHub scope and link to reconnect. Error: GitHub rate limit or token
revoked → clear message + retry + sign out.

### Analysis initiation

Clicking `Analyze` immediately creates the analysis and navigates to `/analyses/:id`. If an analysis for
the same repository is already queued or running, the button opens that one instead of creating another.

### Analysis progress `/r/:owner/:name/analyses/:id`

Vertical step list: Clone → Structure → TypeScript → Quality → Complexity → Dependencies →
Architecture → Testing → Git history → Score. Each step shows state (pending/running/done/failed/skipped),
duration when done, and a one-line detail (e.g. "1,284 files, 96,410 lines"). Page polls every 1.5s
while active. On completion it auto-navigates to the dashboard. On failure it shows the failure
reason (size limit, timeout, clone error) with `Retry` and a link back.

### Dashboard `/r/:owner/:name`

Row 1: health score ring (0–100 with grade letter), seven category scores as compact tiles with delta
vs previous analysis. Row 2: health trend chart (all analyses) and finding counts by severity.
Row 3: top findings (5, by severity), hotspots (churn × complexity, top 8), dependency health summary,
testing health summary. Every tile links to the relevant filtered view. "How is this computed?"
opens a side panel with the formula and inputs.

### Findings `/r/:owner/:name/findings`

Left: filter rail (severity multi-select, category multi-select, file path prefix). Top: search, sort
(severity, file, rule), result count. Main: virtualized table (severity, rule, message, file:line).
Selecting a row opens a detail panel on the right (wide) or a sheet (narrow): title, severity,
category, evidence block, recommendation, file path with GitHub link at the analyzed commit, related
findings in the same file, `Create GitHub issue` (owner only, with prefilled body preview).
All filters live in the URL.

### Architecture `/r/:owner/:name/architecture`

Interactive graph of internal modules (directory-level by default, expandable to files for a
directory). Node size = lines of code, colour = finding density, edge = import. Toolbar: layout
(force/hierarchical), highlight cycles, search node, show only cycles. Side panel on select: fan-in,
fan-out, instability, files, findings in that module. Below the graph: table of detected cycles and
the most-depended-upon modules.

### History `/r/:owner/:name/history`

List of analyses (date, commit, score, finding count, duration, status). Select two analyses (or
"vs previous") to compare: score deltas per category, findings resolved / new / unchanged, metric
deltas (files, lines, complexity, coverage-related counts, dependency counts).

### Settings `/settings`

Sign out. Delete all my data (repositories, analyses). Shows the GitHub scopes granted.

## State catalogue

| State | Treatment |
| --- | --- |
| Loading (first) | Skeletons matching the final layout; no spinners in content areas. |
| Loading (refetch) | Keep content; subtle progress bar under the header. |
| Empty (no analyses) | Illustration-free empty card: what to do + primary action. |
| Empty (filters exclude all) | "No findings match" + `Clear filters`. |
| Error (API) | Inline error card with message, request id, `Retry`. |
| Error (auth) | Redirect to `/` with a toast explaining the session expired. |
| Stale (viewing old analysis) | Amber banner in the repository shell: "Viewing analysis from … · View latest". |
| Running elsewhere | Shell shows "Analysis in progress" chip linking to progress view. |

## Accessibility

- Colour never carries meaning alone: severity and score always have a label or icon.
- All charts have a text summary and a data table toggle.
- Contrast ≥ 4.5:1 for text in both themes.
- Focus is trapped in dialogs and returned on close.
- Live regions announce analysis step completion.

## Responsive behaviour

- ≥1280px: full layouts with side panels.
- 768–1279px: filter rail collapses to a popover; detail panel becomes a sheet.
- <768px: single column; tables become stacked rows; the graph shows a simplified list view with a
  "Open graph" button that renders the graph full-screen.
